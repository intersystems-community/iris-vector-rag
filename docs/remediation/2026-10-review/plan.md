# Remediation plan: October 2026 code review

Status: **decided**, 2026-10-02. Every one of the 162 findings in [findings.md](findings.md) has a
Fate, and every decision behind this plan is a closed ticket in [tickets/](tickets/). This file
is the hand-off: take a feature from the table, read its row and the decision records it names,
and run `/speckit.specify` on it. Executing anything here is outside the map that produced it.

## How to use it

- **One feature, one spec-kit feature, one branch** `remediation/<feature>` cut from the merged
  `master` (ticket [base branch](tickets/G8-base-branch-for-fixes.md)). Nothing is pushed until
  the maintainer says so.
- **Test-first, with an end-to-end gate per story** (standing rule). The per-feature scope,
  behaviour change, test outline and risks are in the draft,
  [research/P1-draft-feature-grouping.md](research/P1-draft-feature-grouping.md), section "Scope,
  behaviour change, tests, risks per feature". The draft uses the names before consolidation;
  the mapping is in the last section of this file.
- **Which fixes need the IRIS gate** ([verification ticket](tickets/G9-verify-fixes-needing-iris.md)):
  storage, schema, migrations, ObjectScript, connections and entity ingestion. Logic-only fixes
  (fusion scoring, dimension validation, error reporting, the entity-services result shape, the
  connection-settings resolver) may be verified by unit tests alone.
- **Fail loudly** is the convention everywhere: no silent fakes, no swallowed exceptions, and
  degraded behaviour only on an explicit, visible opt-in.
- **Releases:** behaviour changes are announced under the existing `## Unreleased` section of
  `CHANGELOG.md` (0.15), under Changed and Removed, with no major bump. Deprecated features ship
  a warning in one release and are removed in the next.
